# School-Provisioned Login Mode

Public self-registration is disabled.

## Student sign-in
Students can sign in using either:
- their institutional email address, or
- their 6-digit Student ID.

Both use the school-issued/default password. A student may change that password later from the Profile drawer.

## How accounts are created
1. System Administrator opens **Elections**.
2. Save/create the active election before the roster freeze date.
3. Prepare a CSV with these columns:
   - `studentId`
   - `fullName`
   - `institutionalEmail` (legacy `email` is also accepted)
   - `program`
   - `college`
   - `enrollmentStatus`
   - `eligible`
4. Choose the CSV under **School Student Accounts & Voter Masterlist**.
5. Click **Import & Provision School Accounts**.
6. Newly created or migrated accounts receive a unique temporary password generated by the trusted backend.
7. A private credential CSV downloads once. Distribute each credential only to the matching student and delete unsecured copies afterward.

## Existing accounts
If a Student ID was previously linked to a self-registered account, the provisioning function migrates that linked Firebase Authentication user to the institutional email and issues a new temporary password.

## Election eligibility
A valid school account and voter eligibility are separate:
- A school-provisioned student may access normal student dashboard features when the account is approved and active.
- Election/voting pages additionally require the current election voter roster to mark the student eligible.

## Deployment
This change adds/changes Cloud Functions and Firestore rules. Deploy them after replacing the project files:

```powershell
npx.cmd firebase deploy --only functions,firestore:rules,firestore:indexes
```

## Provision one student without importing a full election roster
Open **Admin Control → User Directory → Provision School Student Account**. Enter the Student ID, institutional email, name, program, college, enrollment status, and whether the student is an eligible voter. The backend will create or synchronize the account and show a temporary password only when a new password was issued.
